✅ 1. Hvorfor MySQL var riktig valg (og ikke MongoDB/Mongoose)


Litt utdypet (akkurat passe mengde):

✔ Prosjektet ditt har RELASJONER

Booking-system → typiske relasjoner:

Én tenant har mange brukere

Én bruker tilhører én tenant

Én tenant har abonnement

Én tjeneste har mange bookings

Booking må knyttes til ansatt, dato, kunde osv.

Alt dette er klassiske SQL-relasjoner, og MySQL håndterer det elegant.

MongoDB kan også gjøre det, men du må:

håndtere masse manuelt

normalisere selv

passe på dokumentstørrelse

passe på consistency

SQL gjør dette automatisk.

✔ Laravel er bygd rundt SQL / Eloquent ORM

Laravel + MySQL = “native mode”.

migrasjoner

foreign keys

policies

Eloquent-relasjoner

database factories

skalerbarhet

Alt passer sammen uten friksjon.

MongoDB krever:

3.parts drivere

helt annen måte å modellere data

mer custom kode

mindre dokumentasjon

✔ MySQL er tryggere for kritiske data

Booking-systemer krever:

transaksjoner

locking

referensiell integritet

MongoDB mangler mange av disse eller gjør dem mye svakere.

✔ Bransjestandard

Booking, POS-systemer, SaaS-flater → nesten ALLE bruker SQL:

MySQL

PostgreSQL

SQL Server

Det er rett og slett det mest stabile valget.


✅ 2. Hva er Alpine.js — og hva gjør det egentlig?

Kort versjon:

“Alpine.js er et ultralett JavaScript-rammeverk som gir interaktivitet i Blade-komponenter uten at man trenger en tung frontend som React. Det gjør små dynamiske ting som dropdowns, modaler og tilstandshåndtering direkte i HTML.”

Dypere (men kort og enkelt):

✔ Alpine = “Tailwind for JavaScript”

lettvekts, enkelt

inline i HTML

ingen build steps, ingen komplisert struktur

✔ Det du gjorde med vanlig JS før → Alpine gjør enklere

Så ja — du forstod det 100% riktig:

det er ikke ferdige komponenter

det er interaktivitet i eksisterende HTML

du hadde klart dette med vanilla JS, men Alpine gjør det renere og raskere

Eksempler:

Toggle knapp

Vise/skjule paneler

En liten modal

Et dynamisk skjema

Kalender-interaksjon

Step-wizards

Perfekt for Laravel Blade, fordi det holder ting “enkelt og backend-nært”.

✅ 3. Hva er Breeze, Blade, osv — hva er det egentlig?

Dette er en typisk “mange ord”-situasjon, men forklaringen er egentlig veldig enkel.

✔ Laravel Blade

“Blade er Laravels egen templating-motor — basically HTML + enkel logikk.”

DETTE ER IKKE:

React

Vue

noe tungt

noe du må lære som et nytt språk

DET ER:

HTML-side der du kan bruke {{ }} for variabler

loops (@foreach)

if-statements

komponenter

Eksempel:

<h1>{{ $user->name }}</h1>


Du jobber egentlig i HTML, bare med litt superkrefter.

✔ Laravel Breeze

“Breeze er en ferdig pakke som setter opp autentisering, registrering og dashboard for meg, så jeg slipper å gjøre alt fra scratch.”

Det gir deg:

register/login/logout

e-postverifisering

passord-reset

ferdig design i Tailwind

Blade-views

kontrollerne

routing

Det gjør starten av prosjektet superrask, og du kan fokusere på logikken og funksjonaliteten.

✔ Hvordan de henger sammen

Breeze gir filene

Blade renderer dem

Alpine gjør dem interaktive

Tailwind designer dem
